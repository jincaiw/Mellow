### 失败闭环过程（两个真实根因，均在 harness 侧）

1. **code 场景：探针坐标 + caret 复位错误**
   - 点击坐标 `y=110` 落在标题栏/工具栏空白处，输入根本没进编辑器（截图证据：
     `mellow-code-focus.png`，可编辑代码行实际约在 `y=195`）。
   - 且 `focusEditor` 无条件执行 `Ctrl+End`，把 caret 推到围栏**之外**，即使点中代码行
     也会把拼音提交到代码块后面。
   - 修复：`focusPoint` 改 `y=195`；新增 `end: false` 选项让 code 场景跳过 `Ctrl+End`。

2. **全部场景 Undo 假失败：读回动作污染观察窗口**
   - 原实现在每次 `Ctrl+Z` 后都执行 `Ctrl+A/C + Ctrl+S` 读回。该读回会改变
     X11/WebKitGTK 的焦点与编辑器 dirty/disk 状态，使本来有效的 composition undo
     被观察动作打断 —— 表现为「输入 8/8 PASS、Undo 8/8 FAIL」。
   - 修复：新增 `readBackForUndo()`（只保存后读文件，不做 `Ctrl+A/C`），并让所有
     `Ctrl+Z` 连续执行完再读回一次。

> 方法论记录：这两条都属于「探针自身制造失败」。判据是**同一场景的输入通过而 Undo 失败**
> ——若是真实产品缺陷，通常输入阶段就会暴露（composition 丢字/重复）。因此先怀疑观察动作，
> 而不是先改产品。

### 4.2 Linux 侧修复回顾（两个根因，均在 harness 侧）

1. `sidebar-golden.mjs` / `drag-drop-verify.mjs` 仍用 `page.on('dialog').accept()`

2. 三个视觉脚本用 `spawn('npx')`，Windows 上无法执行 `npx.cmd`（ENOENT）。

### 4.3 Windows 侧：**第二处独立根因**（v1.5.15 轮暴露）

v1.5.15 轮 Windows 的「Upload Windows visual golden」显示 ✓ 却无制品 ——
因为 `upload-artifact` 在 0 文件时只 warn，步骤仍判成功。读 job 日志得到：

```
##[error]An error occurred trying to start process
  'C:\Program Files\PowerShell\7\pwsh.EXE' with working directory
  'D:\a\Mellow\Mellow\mellow'. The directory name is invalid.
```

Windows job 的 `actions/checkout` **没有** `path: mellow`（与 Linux job 不同，
仓库落在工作区根），但视觉采集步骤写了 `working-directory: mellow` → 目录不存在
→ pwsh 无法启动 → **步骤一步都没跑**（连 node 都没执行）→ continue-on-error 吞掉错误。

这与 `spawn('npx')` 是**两个独立缺陷**：前者让步骤根本没启动，后者会在步骤能启动后
继续失败。修复：移除该 `working-directory`；制品路径同步去掉 `mellow/` 前缀；
新增护栏（`verify-runtime-qualification-workflow`）按 job 断言
`working-directory` / 制品路径前缀与 checkout 落点一致。

**验证状态**：`workflow_dispatch`（`target=macos-windows`）run `35753364446` 已派发，
结果见 §六。
