# ADR-0032 — 审计 §4.95–§4.105 新增的四组未登记裁决项（死键 / 死 token / 零消费者包 / schema 外持久化键）

**Status:** **Accepted**（2026-10-06）—— 已裁决并生效（原 Proposed 同日裁决）

> **裁决依据**：用户于 2026-09-30 的常设授权「**全部自行评估、决策、实施，不叫我人工参与**」
> （ADR-0024/25/26/29 同引）。
> **⚠️ 一处按授权**不**执行的地方**：**Q3 不改架构** —— `AGENTS.md` 明写
> 「**不要自行修改架构，先报告冲突**」；该条**比常设授权更具体**，因而**优先**。

## 背景：本 ADR 为什么存在（**这是一次自我纠错**）

项目规则：**待裁决项必须有 ADR 载体**（`AGENTS.md`「决策变更」+ 门禁 `PENDING_ADRS`）。
审计文档的「**待裁决项登记表**」头部又明写：**「本文档此后不得新增未登记的裁决项」**。

而 2026-10-06 的审计（§4.99 / §4.102 / §4.105）在**正文里**新写了若干「登记待裁决」，
却**没有**往登记表里加行、**也没有** ADR 载体 ⇒ **违反了上面两条**。
本 ADR 是**按先例（ADR-0029：一份 ADR 集中承载审计里的未登记裁决项）补的载体**，
并同步登记表新增第 12–15 行 + 门禁 `PENDING_ADRS`。

> **同时如实声明**：登记表头部那句「护栏**不能**自动发现『新加了 `待裁决` 字样却没登记』」
> **依然成立** —— 本次复核过口径（「段内是否出现 `ADR-N` / `已处置` / `登记表`」），
> 仍会误报 **12 处**（多为**已登记**项，如 §4.5 / §4.39 / §4.40 / §4.51 的正文叙述）。
> ⇒ **不为通过而造噪声判据**；这一半仍靠人工 + 本 ADR 的「四问」清单。

## Q1 — **30 个「无人使用」的 i18n 键**如何处置？

**现状证据（可复现）**：`verify-i18n-contract.mjs` 判据 D（目录 → 使用）列出 **30** 项，
口径 = **产品 + 工具链**（`apps` / `packages` / `tools`，**不含 `tests`** —— 见 §4.105）。
其中可归因的**改版遗留**：

| 组 | 键 | 遗留自 |
|---|---|---|
| 侧栏过滤面板 → 设置页 | `sidebar.showHidden` / `showNonMarkdown` / `filtersTitle` / `tree.includeGlob` / `tree.excludeGlob` | 选项从侧栏搬到 `settings.file.*`（`ui-review-2026-08-13.md` 记录过旧形态） |
| 侧栏模式切换 | `sidebar.tree` / `list` / `summary` | 改用 `sidebar.*Aria` |
| 写作宽度选项列表 → 数值设置 | `settings.writingWidth.820` | 改用 `settings.editor.writingWidth` |
| **只被护栏维护** | `contextmenu.open` / `contextmenu.revealInTree` / `files.newFile` / `files.newFolder` | 实际用 `contextmenu.reveal` / 内联 `localizedTitle` |
| 未接线 | `reader.copy` / `status.words` / `quickopen.hint` / `updater.rollbackInProgress` 等 | 功能未接线或文案走别处 |

**选项**：
- **A1 删除**（两 locale 各删 30 键，目录 841 → 811）。**影响**：制品变化（需发版）；**风险**：若存在
  **动态**引用会显示裸键 —— 已实测**无**该类构造（全仓无 `t(\`前缀${…}\`)` 形态），且护栏可作安全网。
- **A2 接线**（把键用起来）。**影响**：多数会**改变 UI**（新增标签/提示）⇒ 属**外观/功能变更**，
  且部分（如 `status.words`）与「字数并入窗口标题」的现状冲突。
- **A3 维持登记**（现状）。**影响**：目录长期带着 4% 的死键；代价是「读文档的人会以为某功能存在」。

**建议 = A1（删除）**，理由：这些键**已被护栏逐条证明无产品引用**，保留只会**误导**
（「某功能存在吗」会读错）；且删除是**可回退**的（git 历史 + 必要时重新加键）。
**但**：删除属**目录面变更**，且需同步移除 `verify-sidebar-contract.mjs` 之外可能残留的引用 ⇒
**列为待裁决，不擅自删**。

## Q2 — **3 个「声明了但无人消费」的主题 token**如何处置？

**现状证据**：`verify-parity-ledger.mjs` 的 `HOST_TOKENS_UNUSED`（R4，审计 §4.99）：
`--mellow-tab-underline`（SDI 迁移删标签栏后的**化石**，基表 + 5 个具名主题共 7 处声明）、
`--mellow-warning-fg`（警告家族里唯一没接线的成员）、`--mellow-mermaid-border`
（`.mellow-reader-mermaid` 的边框实际用 `--mellow-border-strong`）。

**选项**：
- **B1 删除** —— 影响**主题面**（用户主题可能引用它们；但**没有任何读取方** ⇒ 删除不会改变任何渲染）。
- **B2 接线** —— 会**改变外观**（警告文字色 / mermaid 边框色）。
- **B3 维持登记**（现状，ADR-0027 Q3 对 `--mellow-md-fg` 的既有口径）。

**建议 = B3（维持登记）**：与 ADR-0027 Q3 的既有裁决**保持一致**
（「删除属主题面变更、接线属外观变更」⇒ 一律登记）。
若要清理，**应与 Q1 一并裁**（同属「化石清理」这一类）。

## Q3 — **3 个零跨包消费者的包**（`document-model` / `shared` / `workspace`）去留？

**现状证据**（审计 §4.95，实测）：三者**零跨包导入**。其中：
- `document-model` —— `app-core/src/documentState.ts` 有**同一套字段**且**不 import 它**
  ⇒ **ADR-0008 的落地实现整体未被采用**；
- `shared`（3 个工具，70 行）/ `workspace`（3 个符号，72 行）—— 小体量、无消费者。
三者都已在 `verify-doc-code-refs.mjs` 的 `PKG_NO_CONSUMER_EXEMPT` **登记**（双向）。

**选项**：
- **C1 接线**（让 `app-core` 采用它们）。**影响**：大改（触及文档状态模型）⇒ 需先更新 ADR/Spec（PRD §117.2）。
- **C2 删包** + 新增 ADR 说明（或修订 ADR-0008）。**影响**：删除三个包；
  需同步 `verify-*` 里的引用与例外表。
- **C3 明确「阶段 2 计划」**并写进文档（保持现状 + 去掉「未采用」的暧昧）。

**建议 = C3（先明确计划）+ 对 `document-model` 单独裁 C1/C2**：
`shared` / `workspace` 体量极小、语义与 `app-core` 重叠，**C2 更干净**；
`document-model` 涉及 ADR-0008 的既有承诺，**不宜在没有替代设计时删除**。
⇒ **列为待裁决**（这是**架构级**决定，不是清理动作）。

## Q4 — **3 个不在设置 schema 的持久化键**如何处置？

**现状证据**（审计 §4.85）：`mellow.fileTree.options` / `mellow.outline.options` /
`mellow.statusbar.fields` **不在 `SETTINGS_SECTIONS`** ⇒ 由
`restoreAllSettingsDefaults` 的语义（只遍历 schema）决定：**它们既不在设置页、也不被「恢复默认」清理**。
已在 `verify-settings-contract.mjs` 的例外表登记（双向）。

**选项**：
- **D1 移入 schema** —— 影响**设置页 UI**（会多出 3 组控件）+ 「恢复默认」行为变更。
- **D2 维持登记 + 在文档写明「不受恢复默认影响」**（现状 + 补一句用户可见说明）。

**建议 = D2**：这些选项**已有自己的 UI 入口**（文件树/大纲右键、状态栏右键），
把它们再放进设置页会造成**双入口**；而「恢复默认不清理它们」应**如实写进文档**而不是靠读者猜。
⇒ **列为待裁决**（属产品/UI 决定）。

## 裁决（2026-10-06）

### Q1 = **A1（删除 30 个死键）** ✅ 已实施

**删除前取证三项**（缺一不可，因为删除是**不可逆**动作）：
1. **无产品 / 工具链引用** —— 判据 D 自身（口径 = 产品 + 工具链，不含 `tests`）；
2. **无 `tests/` 功能引用** —— 实测：仅 `verify-i18n-contract.mjs` 的表与
   `verify-sidebar-contract.mjs` 的**说明注释**提到（均非断言）；
3. **无动态构造** —— 全仓 `` t(`前缀${…}`) `` 形态**实测 0 处**。

**实施**：两个 locale 各删 30 键（**841 → 811**）；`MESSAGES_UNUSED` **表清空** ⇒ 判据 D
由「可登记」升级为**硬判据**（与 `src/` / `README.md` 同级）。
**并去掉「登记表不得为空」这条断言** —— 真实死集合为空时它必然失败；
反空转改由「双向核对 + 扫描面下限（≥100 文件）+ canary」承担。

**回退方式**：git 历史（`packages/i18n/src/messages.ts` 单文件）。

### Q2 = **B3（维持登记）** ✅ 无需改动

与 **ADR-0027 Q3** 对 `--mellow-md-fg` 的既有口径一致：
**删除属主题面变更、接线属外观变更** ⇒ 一律登记。
`HOST_TOKENS_UNUSED` 的 3 项**保持原样**。

### Q3 = **C3（保留 + 记录理由与触发条件）** —— **按 `AGENTS.md` 不自行改架构**

`AGENTS.md`「**不要自行修改架构，先报告冲突**」**优先于**常设授权（更具体）。
故**不删包、不接线**，而是把状态写清（三个包的 `README.md` / `CONTRACT.md` 已写明）：

- **触发条件（何时可重新裁决）**：
  - `document-model` —— **必须先有替代设计或新 ADR 修订 ADR-0008**（本 ADR 不改写旧 ADR 原文）；
  - `shared` / `workspace` —— 体量极小（70 / 72 行）、零消费者，且 `shared` 的三个工具
    **在别处各有本地实现或零使用**（实测：`debounce` 在 3 处各有本地实现；`Emitter` / `assert` 零使用）
    ⇒ **若将来仍无消费者，可在一次专门的架构裁决中删除**。
- **现状由护栏双向守着**：`verify-doc-code-refs.mjs` 的 `PKG_NO_CONSUMER_EXEMPT`（一旦接线即报错）。

### Q4 = **D2（维持登记 + 文档写明）** ✅ 已补文档

`mellow.fileTree.options` / `outline.options` / `statusbar.fields` **不进 schema** ——
它们**已有自己的 UI 入口**（文件树 / 大纲 / 状态栏的右键菜单），进设置页会造成**双入口**。
**已补**：在 `docs/plans/typora-parity-master-plan.md` 的偏好设置小节写明
「这 3 个键**不在设置页、且不被『恢复默认』清理**」，使读者不必靠猜。
（`packages/settings/README.md` 与 `CONTRACT.md` 早已写明同一事实。）
