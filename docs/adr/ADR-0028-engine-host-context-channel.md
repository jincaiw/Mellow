# ADR-0028 — 引擎侧「宿主上下文」通道：统一桥 vs 逐项加桥

**Status:** **Accepted**（2026-10-01）—— 已裁决并生效（原 Proposed 同日）

## 裁决（2026-10-01）

> 依据：用户于 2026-09-30 授权「**全部自行评估、决策、实施，不叫我人工参与**」
> （ADR-0024 / 0025 / 0026 的裁决节均引此授权）；本会话用户连续指示「继续」「未完成，继续实施」，
> 而本 ADR 是唯一挡住 `P0-I18N-001` 的东西。
> **授权不等于降低举证标准**：下面每条裁决都指向可复核的证据或项目自身的规则。

### Q1 = **A2**（逐项加桥：新增 `__MELLOW_ENGINE_LOCALE__`），**不建统一桥**

**理由（按证据，不是按偏好）**：

1. **A1 的主要论据已被本会话的新护栏削弱。** §4.54 主张统一桥的核心理由是
   「逐项加桥 → **没加的那部分静默失效**」。而本会话已把这条风险**变成会红的判据**：
   - `verify-parity-ledger.mjs` 的 **R1 可达性**（引擎里每个 `var(--mellow-X)` 必须可达：
     md ⇒ 两端都有；非 md ⇒ 必须在登记表）—— 这正是「静默失效」的检测器；
   - `verify-i18n-contract.mjs` 的引擎文案登记表（79 条，双向核对）。
   **即：主要风险已被机制覆盖，A1 的边际收益下降。**
2. **A1 的改动面与收益不匹配。** 统一桥要改动既有 **36 个** `__MELLOW_*` 中的一部分，
   而其中 `__MELLOW_THEME_TOKENS__` 等牵动**引擎多个表面的外观** → 需重采三平台视觉基线。
   收益是「以后加宿主状态不用再加桥」，但**当前只差 1 条**（locale）。
3. **A3（直读 localStorage）被否**：引擎与宿主会**隐式耦合键名**，且 localStorage 变更
   **不触发引擎重渲染**（引擎 UI 多为按需构建，但已渲染的部分不会更新）→ 只适合启动期一次性读取，
   不足以承载「切换语言后界面立刻变」。
4. **保留的缓解**：新增的 locale 桥**必须**同时进 `verify-adapter-contract.mjs` 的桥完整性判据
   （每个 `__MELLOW_*` 必须有声明处 + 读取处），避免「死桥」。

> **与 ADR-0027 的关系**：A2 选定后，ADR-0027 的 Q1（面板 token 走既有 md 桥）与本案**解耦** ——
> 面板 token 不需要新桥。故两份 ADR 可各自成立（原「应一并裁决」的顾虑随之消解）。

### Q2 = **B1**（引擎**自带**文案目录）

**理由**：引擎当前 `dependencies: {}` —— 「**零工作区依赖**」是一条**已有的架构性质**
（引擎可独立复用/嵌入）。B2 会**首次打破**它，并把整个应用目录（zh 841 / en 841 键）
带进 iframe 产物。两套目录的「可能漂移」风险改由**护栏交叉核对**兜住（键集不得重叠 +
`tEngine` 的键必须在引擎目录中存在），比牺牲架构性质更划算。

### Q3 = **C1**（默认 **zh-CN**）

**理由**：与 `mdTokens.ts` 的「`MD_TOKEN_DEFAULTS` = 真值」同构，且 Mellow 默认语言即中文
（PRD §87）→ **未接桥时 = 当前行为**，接线本身**不产生行为变更**（可安全先行落地）。

> **本 ADR 的由来**：`P0-I18N-001`（引擎侧 English 完整性）是未闭环项里唯一 `blockedBy`
> 指向**实现**的一项。准备接线时发现：**locale 是「宿主上下文到不了引擎」的第三个实例**，
> 而 §4.54 早已记下「与其继续逐项加桥，不如定一个统一的 UI 上下文桥」——
> 该建议**一直没有 ADR 载体**。接线会**替它做选择**，故先立此 ADR。

## 背景

### 一、架构事实（非取舍）

编辑器运行在**独立 iframe**（独立 `document`），宿主的 JS 上下文与 CSS 变量都**不会自动继承**。
宿主状态进入引擎**只有一条路：显式桥**（`window.__MELLOW_*`）。当前已有 **36 个** `__MELLOW_*`
全局（§4.54 已全量核对：无死桥 / 无断桥）。

**已知的三个「宿主上下文到不了引擎」缺口**：

| # | 缺口 | 现状 | 记录处 |
|---|---|---|---|
| 1 | **locale** | 引擎 UI 文案**硬编码中文**（实测 **79 处 / 8 文件**，见 §4.57） | §4.52 / §4.57 |
| 2 | **非 md 主题变量** | 6 个 `var(--mellow-*)` 恒取 fallback（桥只放行 `--mellow-md-*`） | §4.53 / ADR-0027 |
| 3 | **其它宿主状态** | ——（尚未遇到，但形态可预期） | §4.53 |

三者形态相同：**引擎在独立 document 里，宿主上下文需要显式桥接，而桥是逐项加的** ——
于是「**没加的那部分静默失效**」。

### 二、本次要接的线：locale

引擎侧实测 **79 条硬编码中文文案 / 8 个文件**（§4.57；台账原记 43 条 / 5 文件，**少计一半**）。
要让 English 界面下引擎文案也变英文，必须把 locale（或译文）送进 iframe。

**一手基线**：Typora 的 `.strings` 文件**键即英文源串**（`Close = 关闭`、`Columns = 列`），
故英文真值可从本机 `zh-Hans.lproj/{Menu,Front,Panel}.strings` 的键直接取得 ——
本轮已取到 **17 条**（如 `Find` / `Replace` / `All` / `Case Sensitive` / `Regular Expression` /
`Download` / `Open` / `Rename` / `Heading 1..3` / `Strike` / `Quote` / `Emphasis` /
`Align Left|Center|Right` / `Delete Table`）；其余（表格工具栏文字标签、图片操作 tooltip 等）
Typora 用**图标**而非文字 → 属 **Mellow 自译（参数原创）**，须在实现时逐条标注。

## 待决问题

### Q1 — 引擎侧宿主上下文的通道形态？

| 选项 | 内容 | 后果 |
|---|---|---|
| **A1** | **统一 UI 上下文桥** `__MELLOW_UI_CONTEXT__`，一次承载 locale + 主题 token + 后续宿主状态；旧桥保留为兼容层或迁移 | 一次性说清边界；新增宿主状态**不必再加桥**；代价是**要改动既有 36 个桥中的一部分**，且需重采视觉基线 |
| **A2** | **逐项加桥**（现状延续）：再加一条 `__MELLOW_ENGINE_LOCALE__` | 改动最小、与既有 36 个桥同构；但**第 4、5 个缺口出现时仍会静默失效** —— 这正是 §4.52/§4.53 两次踩到的形态 |
| **A3** | 引擎**直读 `localStorage`**（不建桥） | 零桥；但引擎与宿主**隐式耦合键名**，且 localStorage 变更**不触发引擎重渲染**（只适合启动期一次性读取） |

### Q2 — 引擎文案的**真值源**在哪？

| 选项 | 内容 | 后果 |
|---|---|---|
| **B1** | 引擎**自带目录**（`engineI18n.ts` 内含 zh/en 两套） | 保住引擎「零工作区依赖」（当前 `dependencies: {}`）；引擎可独立复用；代价是**两套目录**（需护栏交叉核对键集不重叠） |
| **B2** | 引擎**依赖 `@mellow/i18n`**，用宿主同一份目录 | 单一真值源；代价是引擎**首次引入工作区依赖**，且 iframe 产物会带上整个应用目录（或需按需构建） |

### Q3 — 桥未就绪 / 未注入时的**降级**

| 选项 | 内容 |
|---|---|
| **C1** | 默认 **zh-CN**（与 `MD_TOKEN_DEFAULTS`「默认 = 真值」同构，且 Mellow 默认语言即中文） |
| **C2** | 默认 **en-US** |
| **C3** | 不降级：未注入则不渲染文案（显式失败） |

## 建议（供裁决参考，非结论）

- **Q1 → A1**：两个缺口（locale、非 md 主题变量）已各自证明「逐项加桥会漏」，而 §4.54 的全量核对
  说明桥的数量已到 36 —— 再加第 37、38 条的边际收益在下降。**但 A1 的改动面显著大于 A2**，
  且 ADR-0027 的 Q1 尚未裁决（它决定主题 token 走哪条路）—— **两者应一并裁决**，
  否则可能落地两套互不兼容的通道。
- **Q2 → B1**：保住引擎的「零工作区依赖」这一**已有性质**比消除「两套目录」更重要
  （前者是架构约束，后者可用护栏交叉核对兜住）。
- **Q3 → C1**：与 `MD_TOKEN_DEFAULTS` 同构，且「未接桥时 = 默认语言」语义最直白。

## 后果（若 Q1=A1、Q2=B1、Q3=C1）

- 新增 `packages/editor-engine/src/engineI18n.ts`：`ENGINE_MESSAGES`（zh/en，79 条）
  + `tEngine(key)` + 桥安装 + localStorage 兜底。
- 宿主侧 `App.tsx` 把 locale 经统一上下文桥下发；`editor-core` 暴露对应 API。
- 8 个引擎文件里的 79 处硬编码中文改为 `tEngine('…')`；`verify-i18n-contract.mjs` 的登记表
  **随之逐条缩小到 0**（该登记表是**待修清单**，不得设条目下限 —— 见 §4.57）。
- 新增护栏：引擎目录与 `@mellow/i18n` 的键集**不得重叠**；`tEngine` 的键必须在引擎目录中存在。
- `P0-I18N-001` 的证据链补「引擎侧 en 界面实测」后，方有资格从 `IMPL` 升回 `AUTO`。
