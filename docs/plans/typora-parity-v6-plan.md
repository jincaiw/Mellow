# Typora 对标第六轮（V6）优化方案

> 依据：2026-09-05 用户提供的 17 组 Mellow v1.4.8 vs Typora 并排截图（markdown-basic-syntax-test.md 全语法走查 + 全菜单展开）。
> 结论先行：**本轮最高优先级不是新样式，而是让 v1.4.8 已实现的渲染真值真正到达真机**——截图呈现的是「v1.4.8 侧栏新壳 + v1.4.7 旧渲染层」的混合态。

---

## §0 P0 根因：真机渲染层陈旧（必须最先解决）

### 0.1 现象矩阵（截图 → 结论）

| 截图证据 | 真机表现 | 库内代码（v1.4.8 已提交） | 判定 |
|---|---|---|---|
| 图1 标题 | h1≈21px、h3≈h4≈h5 同大（旧 [5,3,1] 阶梯） | heading.ts diffs=[20,12,8,4,0,0]（Typora em 阶梯） | ❌ 未生效 |
| 图12 引用 | 文字绿色 | `--mellow-md-quote-fg: #777777` | ❌ 未生效 |

| 图12 行内代码 | 无灰底 | CoreEditor token 真值 | ❌ 未生效 |

| 图1 侧栏 | 单「文件」标签（V5-A1 新壳） | SidebarHeader v1.4.8 | ✅ 已生效 |

### 0.2 证据链

1. 渲染真值全部在库（wysiwygBlocks.ts / mdTokens.ts / heading.ts / table liveView / YAML 卡片，commit 39336f8）。
2. CI 构建链完整：`yarn build (CoreEditor) → editor-core/engine build → build-editor-bundle 抽取 → vite build`（release.yml:57-65）。
3. 本机 Playwright smoke 全绿（无缓存环境）——「**WKWebView 缓存固定名资产**」成为最高嫌疑：`public/editor/engine/*.js` 与 `core-main.js` 文件名无版本指纹，升级覆盖安装后 WKWebView 可能继续命中旧缓存。
4. 本地曾出现旁证：editor-engine/dist 未重建时 bundle 脚本照常抽取旧文件不报错——构建时序缺防护。

### 0.3 P0 修复项

| # | 项 | 说明 |
|---|---|---|
| A | **资产版本指纹** | build-editor-bundle.mjs 在 index.html 引用 `core-main.js` / `engine/*.js` 处追加 `?v={appVersion}`（升级即破缓存） |
| B | **打包自检守卫** | 新增 `scripts/verify-release-bundle.mjs`：校验 core-main.js 含新 heading 值、engine/ 含 wysiwygBlocks.js/mdTokens.js，进 CI |
| C | **一键完整构建** | `scripts/build-editor-all.mjs`：CoreEditor yarn build → wrapper → engine → bundle（消灭「只跑抽取忘了上游构建」时序坑） |
| D | **自检诊断入口** | 帮助菜单「诊断信息」：显示 appVersion + 渲染层指纹（bundle 内容短 hash），用户可自查是否拿到新渲染层 |
| E | （可选）升级后清缓存 | Rust 侧版本变更时清 WKWebView 数据目录（保守：仅当指纹方案仍复发时启用） |

## §2 P2 侧栏与壳 UI

| # | 项 | Typora 行为 | Mellow 现状（截图） | 改法 |
|---|---|---|---|---|
| 2.1 | **侧栏 quickbar 移除** | 侧栏 = 纯文件列表，头部仅「文件」二字 | 「文件▾」+「＋」「＋/」按钮 + 过滤输入框 | 过滤/新建收进右键菜单与命令面板；头部保留单标签切换（Mellow 三模式需要） |

## §5 实施顺序与验收

1. **P0**（半天）：指纹 + 自检守卫 + 一键构建 + 诊断入口 → 立即发 v1.4.10 让用户验证渲染层到位。
2. **P1 + P2**（一批）：视觉残差 + 侧栏/壳 → golden 重刷 + e2e 全绿。
3. **P3 + P4**（一批）：菜单/键位 → menu contract 扩展。
4. 最终发版 **v1.5.0**（渲染层治理 + 菜单体系 = minor 语义），ADR-0020 流程。
5. 验收基线：用户同场景 17 张截图逐项对照复核 + 本地 visual/sidebar golden ±1px。

> 备注：语法高亮与标题阶梯在 P0 修复后需真机复验才能确认是否还需额外代码。
