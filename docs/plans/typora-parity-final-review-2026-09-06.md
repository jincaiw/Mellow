> 状态：**已于 2026-09-06 获用户确认；按 W0 → W8 开始实施。**
> 整理日期：2026-09-06。代码审查基线：`079cd5d`，Desktop 1.5.5，另有既存未提交设置改动。
> 唯一产品基线：PRD V1.2 FINAL；竞品验收基线：Typora 1.14.9（build 7785）。
> 本文是本次审查的完整候选方案，不是新增的并行权威文件。确认后合并回 `typora-parity-master-plan.md`，旧方案只保留历史引用。

## 1. 最终目标与完成定义

### 1.1 用户可感知的目标

熟悉 Typora 的用户打开 Mellow 后，不需要重新学习桌面布局、菜单组织、侧边栏导航和 Markdown 编辑方式；以相同或更少步骤完成任务，获得不更差的响应、排版和文件安全性。

“完全一致或更优”同时要求：

1. **能力一致**：纳入冻结范围的功能不能缺失，菜单不能是空入口，也不能用当前文档操作冒充全局操作。
2. **行为一致**：相同起始状态、输入、快捷键、焦点和文档，得到相同用户可见结果；异常与取消路径也一致。
3. **编辑体验一致**：标记显隐、光标命中、输入法、选区、滚动、表格操作和撤销形成完整行为，而非仅有类似截图。
4. **桌面体验一致**：平台原生菜单、窗口、侧边栏、布局密度和常用操作位置遵循该平台基线。
5. **更优有证据**：无额外常驻干扰，通过任务计时、错误率、性能或安全测试证明收益。
6. **真实性**：保留 Mellow 自有名称、图标和原创资产，不复制 Typora 商标、专有主题资产，不伪装成 Typora。

一致不等于把 macOS 原生窗口按钮照搬到 Windows，也不等于把所有能力全部显示在首屏。默认安静、高频操作可发现、低频能力可进入，是同一目标的组成部分。

### 1.2 范围与不可变约束

- V1：Live、Source、Reader；不恢复已取消的 Split Mode。
- 正式平台：macOS、Windows、Linux；语言：简体中文、English。
- 保留 MarkEdit CoreEditor；CM6 + Lezer、Markdown 单一真源、TypeScript Editor Core、Rust System Core、React Desktop UI。
- 文件 IO 经 Host Adapter / Rust；Editor Core 不依赖 Tauri；不修改只读上游 CoreEditor。
- Tauri 2 按现有 Runtime 决策执行。只有经过复现、定位、优化仍无法达标，才提出新的 Runtime ADR；本方案不授权换框架。
- 不扩大 PRD 冻结范围：Pandoc 相关高级格式等按现有 P1 定义；若“全部 Typora 能力”要求超出 V1，必须另外确认范围变更，不能用 V1 完成冒充全产品覆盖。

### 1.3 权威文档归并

当前存在明确冲突：AGENTS 指定 Master 为唯一权威，而 Master 顶部称被 V4 取代；V4 仍写待确认，后续 V6、B1 又改变默认布局与窗口模型。

确认后的治理动作：

1. 将本方案合并为 Master 新版，保留基线、批准日期、决策记录与验收台账。
2. V4、V6、B1、SDI truth table 标为历史／专项依据，不再独立宣称最终权威。
3. 施工计划只引用 Master 的工作包和验收 ID，不复制一套相互漂移的状态。
4. PRD / Spec 冲突单独提交确认；Accepted ADR 不改写结论，需要变更时新增 ADR。

## 3. 必须确认的产品决策

下表是建议，不是已批准的产品修订。D01 与 D08 涉及冻结范围，必须明确选择；其余可随整版方案一并批准。

| 决策 | 推荐方案 | 代价与边界 |
|---|---|---|
| D01 窗口与标签 | 恢复 PRD 的文档／标签能力；默认外观按平台 Typora：macOS 支持系统习惯的可选标签，Windows／Linux 不强制常显标签；跨平台标签作为不干扰默认体验的 Mellow 增强 | 撤回 B1 对标签、关闭历史的彻底删除，需要新决策记录；若要求 Windows／Linux 完全无标签，则须先修订 PRD §11，不得静默删功能 |
| D02 文件列表 | 恢复“文档列表”，保留文件树、大纲、搜索；视图切换不增加永久工具带 | 需补列表数据、排序、选中项、键盘与滚动恢复 |
| D03 默认排版 | 暂以 PRD / Spec：16 px、820 px、1.65 为准；不是 Typora 测量结论 | 与当前 17／860／1.6 有差异；截图测量完成后如需变化，单独确认规范修订 |
| D04 全局操作 | “保存全部／全部关闭”真实作用于定义中的所有文档；全局 dirty、失败、取消不得遗漏 | 需要跨窗口协调，不是修改菜单文案即可完成 |
| D05 安静默认 | 不增加常驻 Ribbon、AI 面板或重复按钮；原生菜单和上下文菜单承载低频操作 | 高级功能仍可进入；默认隐藏不等于删除 |
| D06 Better | Reader、安全恢复、性能、中文 IME 优化优先；扩展入口按既有 PRD，默认不打断 | 必须提供收益证据，不能以“更好”为由改掉熟悉快捷键 |
| D07 发布口径 | macOS 真机＋Typora 对照；Windows／Linux 当前 SHA 同平台 Runtime Qualification，遵循 ADR-0022 | CI 可证明的运行行为与未实测的物理输入手感分开声明 |
| D08 全量范围 | 分开“V1 冻结范围等价”和“Typora 完整能力覆盖”；先完成 V1，P1 保留具名清单 | 若用户要求一次发布覆盖所有高级导出／集成，先批准扩大范围；不能标注 P1 后仍宣称全 Typora 已覆盖 |

## 4. 桌面布局与视觉合同

### 4.1 基准场景与测量方法

同一机器、屏幕、缩放、语言、系统外观、字体可用性、窗口尺寸、文档、滚动位置和光标状态下对照。分别保存全窗口、正文局部、菜单、侧边栏、表格、图片和设置截图；不只截正文。

每个测量值标记来源：`PRD`、`Typora measured` 或 `proposed`。目前没有 Typora 原生截图测量值，以下数字是 Mellow 合同，不得写成“Typora 精确尺寸”。

| 区域 | 默认与约束 | 需要对照的状态 |
|---|---|---|
| 窗口 | Spec：macOS 1180×780，Windows／Linux 1200×800；最小 900×600 | 首启、恢复、缩放、全屏、多显示器 |
| 原生标题区 | 平台按钮、拖动区、文档名、修改状态；不叠加第二套标题栏 | 已保存、未保存、长文件名、只读、后台窗口 |
| 正文 | 16 px，1.65 行高，最大宽度 820 px；提供 PRD 宽度档位 | 中英文长文、窄窗口、200% 缩放、长公式／表格 |
| 页边距 | 依桌面 Spec／Master，顶部及底部留白须与标题、滚动模式共同测量 | 文首、文尾、打字机模式、短文档 |
| 侧边栏 | 默认宽 260 px，拖动 200–480 px；显隐与恢复按基线 | 隐藏、展开、窄窗、深目录、长文件名 |
| 标签区域 | D01 批准后测量；单文档不产生空白占位或强制额外工具条 | 单个／多个、拖动、关闭、溢出、恢复 |
| 状态区域 | 只呈现基线所需轻量状态；不堆满开发信息 | 字数、选择字数、缩放、只读、同步错误 |
| 查找栏／浮层 | 出现后不遮住命中、光标、输入法候选；退出焦点回原处 | 首尾匹配、零匹配、替换确认、窄窗 |
| 主题 | 自有明暗资产；正文、代码、表格、选择、侧栏一起切换 | 系统切换、用户指定、打印导出独立样式 |

视觉检查包括：内容边界、字号字重、行距、缩进、分隔线、图标光学尺寸、选中态、hover、focus ring、disabled、滚动条、菜单密度和布局跳动。文本抗锯齿差异不得被当作功能缺陷，但也不能用“平台差异”解释正文宽度和控制位置错误。

提议验收容差：同平台可控布局边界误差不超过 2 个逻辑像素；正文换行差异逐段解释；系统菜单／字体光栅化单列豁免。该容差是候选验收规则，须在基准采集后冻结，不作为本轮已达成结论。

### 4.2 禁止的表面一致

- 隐藏标签和文件列表来“简化”截图，却删除实际功能。
- 表格只渲染正确，但不能按熟悉方式进入单元格、换行、撤销。
- 用浏览器页面截图代替 Tauri 原生窗口与菜单证据。
- 静态复制菜单名称，实际执行错误作用域或没有状态绑定。
- 修改默认字号来迎合陈旧测试，而不核对规范与用户效果。

## 6. 编辑体验专项合同

### 6.1 不能遗漏的状态空间

对 E01–E22 和 T01–T06，不只测试“输入后渲染正确”。至少覆盖以下 15 类状态，相关性不适用时必须写原因：

1. 空文档、空块；2. 块起点；3. 块中部；4. 块末尾；5. 前后块边界；6. 折叠或渲染 widget 边界；7. 正向选区；8. 反向选区；9. 跨块多行；10. 中文 IME composing；11. 鼠标点击／拖选；12. 键盘跨块；13. 粘贴／拖放后的异步更新；14. Undo／Redo 后；15. 模式／主题／缩放切换后。

不要求对所有语法做无意义笛卡尔积：安全关键、表格、列表、公式、图片边界做全覆盖；普通渲染组合做成对覆盖并记录遗漏理由。

### 6.2 输入与事务约束

- composition 期间不重建活跃输入 DOM、不提前提交候选，不用 setValue 替代局部 transaction。
- 一次用户结构操作形成合理的可逆事务；异步图片等不能撤销到错误文档。
- 选区通过文档变更映射；渲染刷新不独立移动光标或滚动。
- Source → Live → Source、保存与导出不能顺手全篇格式化；局部操作只改必要文本。
- 菜单、快捷键、上下文入口调用同一 command；不得原生层和 Web 层各执行一次。
- 只读锁定编辑命令，但保留复制、查找与导航，不用全局禁键盘代替。

### 6.3 必测编辑旅程

中文连续输入 → 候选选择 → 输入 Markdown 标记 → Enter 续写 → 列表缩进 → 表格输入 → 跨块选择 → 格式切换 → 连续 Undo／Redo → Source 往返 → 保存重开。每步核对实际文本、selection、dirty、undoDepth（可观测时）及光标视觉位置。

## 7. 侧边栏专项合同

侧边栏是文件管理和文档定位系统，不是装饰面板。

- 文件树：目录层次、展开状态、当前文件和右击目标彼此独立；刷新不重置滚动。
- 文档列表：独立呈现文件集合与排序，不能只是把树的缩进隐藏；列表内容边界和信息密度须补 Typora 实测。
- 大纲：当前文档标题源、层级、折叠、点击定位和滚动跟随；“跟随”不能造成循环滚动或焦点抢夺。
- 搜索：明确当前文件／目录范围；结果项跳转到匹配位置；搜索期间的 stale 结果不能覆盖新查询。
- 各视图独立保存筛选、滚动、展开和选择状态；切换文档时清理不适用状态。
- 鼠标 hover 才出现的操作必须有键盘和上下文替代；触控板滚动不误触移动文件。
- 隐藏侧栏后正文重新居中；显示时避免整页跳到另一段；拖动宽度期间不卡输入。
- 大目录采用增量加载／虚拟化等现有架构允许的措施，先测量瓶颈，不预设重写。

验收素材至少包含：空目录、单文件、三层目录、同名不同路径、中文长名称、隐藏文件、无权限子目录、大目录、外部重命名和删除。所有破坏性操作使用专用测试目录，不使用用户工作文档。

遵循 ADR-0023：`menuSchema → 命令注册／平台菜单／快捷键／测试合同`，不能增加另一份 Rust 或测试硬编码菜单真源。

快捷键按平台实际能力采集。例如 macOS Cmd+T 与 Windows／Linux Ctrl+T 不得机械等同；官方表中 macOS 快速打开与 Windows 快速打开也不同。文本字段获得焦点时，Cmd/Ctrl+A、复制、撤销等应作用于当前字段，而不是误操作正文。系统保留快捷键不能被网页层抢占。[平台快捷键参考](https://support.typora.io/Shortcut-Keys/)

## 9. 窗口、文件与关闭安全状态机

### 9.1 打开行为真值表

先补 Typora 原生观察，再冻结 `origin × windowState × dirty × samePath × preference` 表。不能根据菜单 action 名或单次点击推断所有打开方式。

| 起始状态／来源 | 强制安全合同 | 待基线确认的体验差异 |
|---|---|---|
| 空白 clean 窗口打开文件 | 不无故丢失有价值状态；打开成功才切换身份 | 复用窗口／标签策略 |
| 已保存 clean 文档打开另一文件 | 原文件不被修改；历史定位可恢复 | 当前窗口替换／新窗口／标签 |
| dirty 文档中打开另一文件 | 保存／不保存／取消完整；失败不得继续替换 | 原生提示文本与默认按钮 |
| 新建未命名 dirty 文档 | 取消另存为后留在原文档 | 草稿恢复与关闭历史 |
| 已打开同路径文件 | 防止互相覆盖；定位或协调写入 | 聚焦已有窗口／允许多视图 |
| 文件树／列表／最近／快速打开 | 共用文件安全逻辑，不各自绕过门禁 | 单击、双击和修饰键语义 |
| 系统打开／CLI／链接／拖放 | 参数验证、目标窗口选择、失败提示 | 新窗口与已有窗口偏好 |
| 外部修改＋本地 dirty | 保留两份可恢复版本；明确选择 | 提示／比较／重载具体 UI |

### 9.2 全局保存与关闭

建议协议：主协调者枚举文档身份及窗口 → 读取当前 revision／dirty → 逐项保存或确认 → 汇总失败与取消 → 对已获授权且 revision 未再次改变的目标执行关闭。此为设计方向，具体通过现有 Host API 扩展，不允许 UI 直接写文件。

必须防止：保存中继续输入后错误清 dirty、同路径两个窗口同时写、关闭期间新窗口加入导致漏算、重复 close 事件导致双弹窗、取消后继续关闭其他未经确认的文档。

对于“取消全部关闭”时已关闭的 clean 窗口是否恢复，先按基线采集并冻结，不承诺无法原子保证的全局回滚。任何情况都不得丢失未保存内容。

## 10. 设置、导出与 Better 的边界

设置逐项核对：分类、标题、说明、默认值、取值范围、即时生效、重启提示、持久化、跨窗口广播、恢复默认、双语、键盘与可访问性。不能只比设置项数量。

导出采用独立矩阵：格式 × 文档语法 × 资源路径 × 主题 × 分页 × 平台。内置 HTML／PDF／打印与依赖 Pandoc 的能力分开验收。输入文档不可被导出操作修改，取消不可残留被误认为成功的结果文件。[导出参考](https://support.typora.io/Export/)

Math／Mermaid／HTML 的支持范围必须列到语法 fixture，不使用“已接入库＝完全兼容”的判定。图片离线、相对路径、字体缺失、长表跨页必须有明确结果。

Better 只在以下条件下合并：不增加高频步骤，不改常用键位，不抢焦点，不显示默认额外面板，提供可关闭方式，并有同条件任务证据。AI、Slash Commands、Command Palette 等只按既有 PRD 能力定位，不借本轮对标新增范围。

## 12. 自动化、原生对照与验收门槛

### 12.1 六类证据各自独立

| 类型 | 验证内容 | 不可替代项 |
|---|---|---|
| AUTO | 单元、命令、状态机、DOM／浏览器、菜单契约、Rust IO | 不能证明原生菜单和物理 IME 手感 |
| NATIVE | 原生窗口／菜单、对话框、焦点、系统打开、剪贴板 | 浏览器 mock 不能替代 |
| VISUAL | 同环境同状态截图比较与差异说明 | 无截图不可 PASS；有截图也不能证明交互正确 |
| IME | 简体中文真实输入、候选、组合取消、选区、滚动 | 合成 composition 事件只是补充 |
| FILE | 原始字节、revision、权限／写入失败、恢复与冲突 | 截图“看着一样”不能证明保真 |
| PERF | release 同机外部计时、输入延迟、内存和大文件 | 调试构建／内部假时钟不能替代用户延迟 |

### 12.3 发布阈值

依据 PRD §131–132：总分至少 92/100；Live 至少 24/25，caret／IME／Undo 必须 15/15，文件安全必须 5/5。

| 维度 | 权重 |
|---|---:|
| Live 编辑 | 25 |
| Caret／IME／Undo | 15 |
| 桌面布局与侧边栏 | 15 |
| 表格与图片 | 15 |
| 菜单与快捷键 | 10 |
| 导出 | 10 |
| 性能 | 5 |
| 文件安全 | 5 |

至少 27/30 个任务耗时不超过 Typora 的 105%；关键任务不能慢超过 15%；错误率不更高；IME 与数据丢失问题为零容忍。评分不能抵消数据安全、IME 或缺失核心能力的阻断。

性能按 PRD §109–110 和性能 Spec：启动 P95 ≤1.2 秒，1 MB 打开 ≤250 ms，10 MB 打开目标 1–1.5 秒；普通输入 P95 <16 ms，大文件 <32 ms。计时边界、样本量、硬件、release 构建与原始样本都必须保存，P95 小样本不得包装成稳定统计结论。

采用 Spec 基础语料：1／5／10 MB、100k 行、600×8 表格、100 个 Mermaid、1000 张图片；启动／打开／保存按 Spec 最低重复次数，输入至少 100 次，正式 P95 增加足够样本并记录置信局限。>5 MB 或 >50000 行的大文件策略必须保留编辑、保存、查找、Source 和大纲等规定能力。

### 12.4 三平台证据

macOS 在本机实际应用完成 Typora 对照和中文 IME。Windows／Linux 按 ADR-0022 在当前提交的同平台 CI runner 执行 Runtime Qualification，保留 workflow URL、SHA、artifact、日志、录屏／截图和测试输出；Linux 按门禁要求覆盖 fcitx5 等输入路径。

禁止把上一提交成功、只有编译成功、不同运行时的浏览器测试或 mock 当作本次正式运行验收。CI 无法覆盖的真实硬件手感列为限制，不能虚构用户现场测试。

## 13. 缺陷处理、追踪与变更控制

每个缺陷必须包含：关联矩阵 ID、环境与 SHA、fixture、初始状态、最短复现、Typora 证据等级、Mellow 实际结果、源文本差异、风险等级、根因、最小修复范围、回归用例和结果。

- 阻断：数据丢失、保存错误、IME 吞字／重字、无法撤销的正文破坏、核心操作不可达、运行时崩溃。
- 高：高频操作不等价、错误全局作用域、文件列表缺失、导航／焦点错误、明显性能不达标。
- 中：非阻断布局偏差、状态不一致、低频菜单／文案／可发现性问题。
- 低：不影响行为的细节；仍需在“完全一致”声明前关闭或具名豁免。

验收台账建议字段：`id, scope, platform, locale, fixture, command, expected, evidenceLevel, auto, native, visual, ime, file, perf, commit, status, exception, approver`。状态仅允许 `NOT_RUN / PASS / FAIL / BLOCKED / N_A`，N_A 必须给理由。不得以已有测试文件或字符串匹配成功直接标记完整体验 PASS。

修复遵循“复现 → 根因 → regression test → 最小修复 → 局部测试 → 跨模块回归 → 原生对照”。若根因要求改变 Accepted ADR，停止该项实现并提交新 ADR 供确认。
